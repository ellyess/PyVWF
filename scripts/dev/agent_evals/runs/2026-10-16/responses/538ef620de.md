**Verdict:** REVISE

**Blockers**

1. **The proposed resolver is not the one training uses.** Harness runs build `EntsoeFileSource` per split (`src/vwf/harness/driver.py:75-77`). Each split reads one file: `<c>_grid_points_{fleet_year}.csv`, where `fleet_year` is the last training year for train and the test year for test. If that file is missing it falls back to `<c>_grid_points.csv` (`src/vwf/sources/entsoe_files.py:56-87`). `load_year_specific_grid_points` (`src/vwf/loaders/country_level_loaders.py:104-184`) is only reached through the legacy `load_country_data_with_year_specific` path (`scripts/analysis/train_all_bias_corrections.py:487`). The audit would list seven per-year files that a harness run never reads, and it would miss the test-year grid, which is the one every reported test-year figure is computed on. That function also raises when no per-year file exists, even where training falls back to the static grid. So the audit would stop on exactly the uniform-grid regions it is meant to identify. And it returns DataFrames, not paths, so "recording the names it constructs" means re-implementing the name pattern. Fix: instantiate `resolve_source(spec, split)` for both splits of each config and record `_grid_points_path()`.

2. **The current files cannot label past figures.** The two earlier Belgian figures were computed on whatever grid existed at the time. Grids have been rebuilt since (`docs/findings/method-country-level.md` §5). The manifest hashes curves and models (`src/vwf/harness/provenance.py:79-93`) but not the grid file. Fix: label old figures only where the run directory itself proves which grid was used. Otherwise mark them "grid unknown". Add the grid path and its SHA-256 to the manifest so future figures carry their grid.

**Should fix**

- Key the table by config file, not by region. `configs/regions/be.toml`, `configs/regions/scorecard/be_country.toml` and the study configs can differ in training years. Each row should state its training years and its single test year.
- Checking point counts can never fail on the real risk. Per-year grids share a fixed point set (§5, "Year-specific fleets"), so two different files can have the same count. Compare file hashes instead.
- Point count and total capacity do not show whether a grid is uniform or fleet-weighted. Record the share of points with zero capacity, or the spread of capacities.
- The zone risk is misplaced. `EntsoeZonalFileSource` inherits the grid loading unchanged (`src/vwf/sources/entsoe_zonal.py:55-61`); only its observations are per zone.
- `docs/CONTEXT.md` is absent from this checkout, so I could not check the terms against it.

**What would change my verdict:** The audit calls the harness resolver for both splits of every country-level config, records path, hash and weighting diagnostics, and labels past figures only from evidence in their own run directories.
