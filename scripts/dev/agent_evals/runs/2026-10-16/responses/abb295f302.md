**Verdict: REVISE.** The driver is worth building. The Brazil headline claim and its gate are not, as written.

**Blockers**
1. **The claim was picked after the result was known.** `docs/findings/method-physics-informed.md:262` already says "Zero-shot Brazil matches Brazil's own fitted correction to 0.8%" (0.1062 against 0.1054, line 229). So "names it in advance" is not true. Fix: drop it as a headline and register a test on all five holdouts before running.
2. **The 1% gate is smaller than the seed noise.** BR zero-shot is 0.10619 ± 0.00115 (`docs/findings/method-physics-informed-rerun-prereg.md:137`). 1% of 0.1054 is 0.00105. `src/pyvwf/AGENTS.md` says a difference smaller than the seed spread is not an effect, and section 6 of the findings says close orderings mean nothing. Fix: an equivalence margin of at least the seed spread, plus a resampled interval over BR's 389 rows.
3. **The reference number has moved.** The current BR row is 0.097, k60 fixed, daggered as degenerate (`docs/findings/scorecard.md:965,1000`). At 0.097, zero-shot is about 9% worse, not within 1%. That row is also the best of a sweep chosen on the test year (`scripts/studies/physics-informed/e1_report.py:10`). Fix: name the config (k60 fixed) and the run directory in the registration.
4. **Filling refused units with uncorrected values changes the affine arm.** It no longer matches the harness's restrict-to-common-rows rule (`src/pyvwf/harness/skill.py:175-182`). BR has 2 refused clusters, so this fill moves the gated number. Fix: make common rows the primary score and report the filled version second.
5. **The dry run never checks Brazil.** It only runs where affine covers every model row, and BR's refused clusters mean BR is not one of them. Separately, the two pipelines' uncorrected numbers differ: 0.1386 (cache) against 0.130 (harness). Fix: require the uncorrected arm to match on the shared rows, and map IDs between the two pipelines (389 model rows against 140 scored complexes).
6. **The model's rows are not on disk.** `e1_loro.py:476-518` writes metrics and exclusions, not per-unit frames. Fix: a separate commit that persists them, or the driver refits with the pinn extra.
