**Verdict: REJECT** in its current form. One run that only logs residuals should come first.

**Steelman the objection.** The gate checks for a failure the joint fit almost never has. At k=1 the fit is a one-dimensional monotone root-find. At k>1 it has N unknowns and one equation, so it can close any reachable observation. When the observation is out of reach, an offset hits the bound, and that case is already refused (`correction.py:339`). Any residual that remains comes from L-BFGS-B stopping early. With `ftol=1e-6` on a squared error below 1, the fit stops once a step improves the squared error by less than 1e-6, which is a CF error of about 1e-3. The proposed 1e-3 gate sits on that stopping point, so it would refuse periods more or less at random. What actually makes these offsets untrustworthy is non-identifiability (`data.py:252-256`, `method-correction-identifiability.md`). A fit that closes exactly is no more trustworthy, and a residual gate cannot see that.

**Cheaper test.** Re-run the existing fits for PT k=1 and IT k=3 with one log line recording `result.fun` per period, without any gate. Then tighten `ftol` and see whether the large residuals go away. Also check whether national rows at k>1 really take the joint path. The same national value, averaged with different capacity weights in each cluster, can differ in the last bits, which would make `nunique` over 1 and route the row to the per-cluster solver.

**Simpler explanation.** If RMSE moves, the cause is probably that `format_bc_factors` averages over fewer years, not that bad periods were removed. In PT, unclosable periods would reflect its stale capacity register, which the preregistration already excludes it for.

**Kill criterion.** Drop the idea if the logged residuals are all under 1e-3, or if they shrink when `ftol` is tightened. The proposal's own gates cannot fail usefully: a gate that does nothing (0% refused, RMSE change 0) passes, and the expected effect (under 0.001) is below the 0.002 tolerance.

**Opportunity cost.** There may be no training 2015-2020 / test 2021 window: the national preregistration says only 2015-2018, 2015-2019 and 2015-2021 exist, with test years 2019 and 2023. The scorecard tests on 2023, so this run would not compare with it. Making new windows means regenerating series before the PT and SE capacity registers are fixed and before `capacity_source` exists. That is the step the blocked single-cluster preregistration deliberately put off.
