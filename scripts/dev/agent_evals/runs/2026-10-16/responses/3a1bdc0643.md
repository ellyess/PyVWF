**Verdict: REVISE.** The question is worth answering. The audit as specified cannot answer it, because a "nothing flagged" result is close to guaranteed whatever the truth is.

**Steelman the objection.** The claim is that other studies are clean. The audit can only see one kind of collision: two configurations with different cluster counts writing into one directory. The claim is about collisions in "something the path does not carry", such as the curve library, roughness, weighting or bounding box. Those runs use the same cluster counts, so the second run overwrites the first run's `factors_*.csv` and leaves no stray file to find. There is a second problem. Harness manifests store the field at `manifest["correction"]["cluster_list"]` (`src/vwf/harness/provenance.py:284-288`). Only legacy `PyVWF` runs store it at the top level (`src/vwf/vwf.py:254`). So `manifest.get("cluster_list")` returns nothing for every harness run, and the audit skips them all, the known DK/UK rows included.

**Cheaper test.** Before auditing about 220 runs, run the audit on the two directories already known to be contaminated (DK and UK `train-fold-<year>`). The project rules require testing a check both ways. Even that may miss: the onshore grid (1, 10, 25, 50, 100, 200, 500, 1000) and the offshore grid (1, 2, 3, 5, 10, 25, 50, 100) share five counts. Those files are silently overwritten. The manifest is rewritten last (`driver.py:284`), so whether anything is flagged depends on which configuration ran last.

**Simpler explanation.** A zero count can come from four things, none of them evidence that other runs are clean:
- harness runs skipped because of the key path;
- legacy runs skipped by design;
- same-name files overwritten;
- the last writer's manifest declaring every count present.

**Kill criterion.** None is stated: both outcomes of the gate lead to "proceed". It should be: if the audit does not flag the known DK and UK directories, drop it as an instrument. A sounder audit would compare across runs that share a directory, for example file timestamps against `created_utc`, or a grep of the study scripts for `run_name` values that leave out the varied dimension.

**Opportunity cost.** Small, since the script is read-only. The bigger cost is that the audit leaves the cause in place: `_run_dir` plus `mkdir(exist_ok=True)` (`driver.py:183-185, 249`). A guard that refuses an existing training directory that already has a manifest is cheaper and stops this happening again.
