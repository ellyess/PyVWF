**Blockers**
1. **Wrong resolver.** `load_year_specific_grid_points` (`src/vwf/loaders/country_level_loaders.py:104`) is called only by the batch method at `src/vwf/vwf.py:380`. The harness goes through `resolve_source` (`src/vwf/harness/driver.py:66-78`) to `EntsoeFileSource._grid_points_candidates` (`src/vwf/sources/entsoe_files.py:66-87`). That picks one file per split, `<c>_grid_points_<fleet_year>.csv`, falling back to `<c>_grid_points.csv`. Fix: call `resolve_source(spec, "train"/"test")` and add a public path accessor in `entsoe_files.py`.
2. **Wrong rows.** The harness has no per-training-year grid. It has a train grid for `train_years[1]` and a test grid for `test_years[0]` (`entsoe_files.py:57-64`). Also, `spec.train_years` is a `(start, end)` pair (`configs/regions/scorecard/be_country.toml:12`), so passing it to the loader would load only two years. Fix: one row per region and split, giving the file, point count, capacity, training years and test year.
3. **The loader cannot give names and fails on static-only regions.** It returns DataFrames, not file names. It raises when no per-year file exists, even if the static file does (`country_level_loaders.py:153-158`). So it would "stop" on exactly the uniform-grid regions the audit is meant to find.
4. **Past Belgian figures cannot be labelled from today's files.** Manifests record no grid path or hash (`src/vwf/harness/provenance.py:262-295`, `driver.py:254-260`). Fix: label a figure only where its run's `train_turb_info_<n>.csv` (`driver.py:238-240`) matches the audit's count and capacity; otherwise write "grid unknown".
