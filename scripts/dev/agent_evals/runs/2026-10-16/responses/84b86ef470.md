**Verdict:** REVISE. The aim is worth having. The way the proposal gets there is broken.

**Steelman the objection.** The audit would label figures with a file the run never read. The code picks a grid per split: `EntsoeFileSource._grid_points_candidates` (src/vwf/sources/entsoe_files.py:66-87) tries `<c>_grid_points_{fleet_year}.csv` first, then falls back to the static `<c>_grid_points.csv`. `fleet_year` is the test year for the test split and the last training year for the train split. The proposal sorts a glob and takes the last match, which AGENTS.md forbids by name. For BE that is the newest year's grid, not the test year's or the training-end year's. A region that only has the static file is reported "missing" even though it runs on that file. The glob also misses NO/SE `*_grid_points_zones.csv`. There is a second problem: the grids were rebuilt in the PR #76 era. So a snapshot of today's files cannot say which grid the two earlier Belgian figures used. A referee would call those labels made up.

**Cheaper test.** Before writing a script, list BE's grid directory and compare the sorted-last file with `fleet_year` for its test year. If they differ, that one check settles it. The better fix is also small: have `build_manifest` (src/vwf/harness/provenance.py:247) record `source._grid_points_path()` and its point count. Every future figure would then name its grid at the source.

**Simpler explanation.** If BE's two figures differ, the cause may be the year-specific grid against the static one, a rebuilt grid file, or the curve library. The proposal reads it as uniform against fleet-weighted. None of these can be told apart without the path the run actually read.

**Kill criterion.** None is named. Drop the retroactive labels if the old run manifests cannot show which file was read; at present they cannot.

**Opportunity cost.** Small, but it puts off the real gap: run manifests do not record their input grid. It also sits on the open BE and year-convention question in #67.
