## The problem

The audit reads `cluster_list` at the top level of `run_manifest.json`, but
the harness writes it under the `correction` block
(`manifest["correction"]["cluster_list"]`). Every run therefore appears to
declare nothing, is skipped as predating the field, and nothing is flagged:
a clean answer from a check that never ran. Running the audit first on runs
already known to be contaminated (a known positive) would have exposed it.
A review that names either the wrong key location or the missing known-positive
check on the contaminated runs identifies this defect.

## The review

**Verdict: REVISE.** The audit as specified would report "clean" whatever is on disk. There is also already a counterexample to the expected effect.

Note: this checkout is the older `vwf` tree. It has no `.importlinter`, no `tests/test_public_analysis_api.py`, no `src/pyvwf/AGENTS.md` and no `scripts/dev/`. Those checks do not apply here.

**Blockers**
1. **Wrong manifest key.** `src/vwf/harness/provenance.py:284-288` writes the cluster list under `manifest["correction"]["cluster_list"]`, not at the top level. So `manifest.get("cluster_list")` returns None for every harness run, every run is skipped, and the gate passes by default. Fix: read `manifest["correction"]["cluster_list"]` and `["time_slices"]`, and select training runs by `run_mode == "train"` (`driver.py:287`).
2. **The expected effect is already false.** `scripts/analysis/cluster_sweep_cost.py:80` hard-codes `run_name="sweep-cost"` and takes `mode` as an argument, with the same onshore and offshore grids (lines 44-45). That is the same collision shape. `scripts/analysis/curve_library_study.py:256` also leaves `mode` out of the path. Name these studies in the gate up front.
3. **The check only looks at cluster counts.** File names also carry `time_res` (`driver.py:267`). Check every (slice, k) pair against `cluster_list × time_slices`.
4. **Skipped runs count as clean.** They must count as unknown, be listed by path, and block a "confined" verdict.
5. **There is no known positive.** Before reading any zero, the audit must flag the cluster-selection study's DK and UK `train-fold-*` directories (`cluster_selection_study.py:107,134`).

**Plan**
1. Write `scripts/analysis/undeclared_factors_audit.py`. It reads files and prints, and writes nothing in the tree.
2. Add a second pass over evaluate runs. Compare `metrics.csv` (`num_clu`, `time_res`) with that run's own manifest (`driver.py:446-460`). This shows what was actually scored; the training directory only shows its final, possibly overwritten, state.
3. Add a fast test (`tests/test_undeclared_factors_audit.py`, `tmp_path`) with three cases: a collided directory (flagged), a clean one (not flagged), and an unparseable `factors_fixed_5.bak.csv` (reported).
4. As a separate commit, the root fix: put `mode` in `_run_dir` (`driver.py:183`), or refuse a non-empty run directory. That touches `src/vwf/harness/`, so run `stamp.py realdata`.

Their selections and the `train-final` refits (line 152) must be re-run, not just the extra rows dropped.
