## The problem

The audit reads `cluster_list` at the top level of `run_manifest.json`, but
the harness writes it under the `correction` block
(`manifest["correction"]["cluster_list"]`). Every run therefore appears to
declare nothing, is skipped as predating the field, and nothing is flagged:
a clean answer from a check that never ran. Running the audit first on runs
already known to be contaminated (a known positive) would have exposed it.
A review that names either the wrong key location or the missing known-positive
check on the contaminated runs identifies this defect.

## The review

**Verdict: REVISE**

**Blockers**

1. **The detector can only see one kind of collision, so a clean result cannot support "confined to that study".** `_run_dir` (`src/vwf/harness/driver.py:183`) keys on `code/train-<run_name>`. `run_train` writes `factors_{time_res}_{k}.csv` with no guard and overwrites silently, and `write_manifest` replaces the manifest (`provenance.py:298`). So the "declared" `cluster_list` is the last writer's. The audit flags a run only when two colliding configurations had different k lists. Two cases pass as clean:
   - Two configurations with the same k list overwrite each other's files under the same names.
   - Evaluate directories collide too (`evaluate-<year>-<name>`), so `metrics.csv` and `cor_cf_*` get overwritten. The audit ignores these directories entirely.

   `curve_library_study.py:256` takes `mode` as an argument and keys only on `condition`, which is exactly the shape of the blind spot.

   **Fix:** add a static audit of the 7 `run_train`/`run_evaluate` call sites under `scripts/analysis/`, checking that every dimension a study varies (fleet mode, bbox, years, slice, min size) is in the run name or the output root. Add a content check per run: the unit IDs in `train_turb_info_{k}.csv` against the manifest's `fleet_mode`. Seed a synthetic same-name collision and show the full audit flags it.

2. **The gate leaves some outcomes undefined.** It does not say what happens to runs reported as undeclared or unparseable. **Fix:** count them as not cleared, needing manual review or a re-run, and write that down before running.

**Should fix**

- Check the time slice as well as k. Comparing files on disk against the keys of `manifest["fit_diagnostics"]` (`{time_res}_{k}`, `driver.py:279`) gives a sharper declared set, where that key exists.
- Select training runs by `manifest["run_mode"] == "train"`, not by directory name.
- In the study the configurations ran in this order: DK offshore, then DK onshore (`cluster_selection_study.py:55`). So the onshore rows took in leftover offshore files at k = 2, 3 and 5, and the shared counts were overwritten. Say which rows and which k values are contaminated, and that offshore rows are clean only if the output directory had not been used before.
- Re-running without fixing the path key, for example putting `mode` into `name` at line 107 or refusing a non-empty run directory, will collide again.
- The negative control comes from the same study, so it cannot exercise a false-negative mode.
- `docs/CONTEXT.md` does not exist in this checkout.

**What would change my verdict:** add the call-site audit and the content check, show a synthetic same-name positive firing, and fix the treatment of undeclared and unparseable runs in the gate, all before the audit runs. Then a null result would mean something.
