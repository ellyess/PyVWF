## The problem

The comparison is not like for like. The affine column is read from an old
cluster sweep that the scorecard has since replaced, so it is not the current
in-region affine correction. And it is scored on the harness's common rows,
which leave out every unit in a cluster whose affine fit was refused, while
the model is scored on all its test rows; the left-out units are harder, so
the affine figure is flattered. A review that names either the superseded

## The review

**Verdict:** REJECT

**Steelman the objection.** The result is already published. Section 3 of `method-physics-informed.md` has Brazil's zero-shot RMSE at 0.1062 against an in-region affine RMSE of 0.1054, and says "matches ... to 0.8%". A 1% gate set after seeing 0.8%, and read for the one region of five where it lands, is a post-hoc threshold made to look preregistered. The prespecification registers no affine comparison (only P1 to P3). The comparator is also weak. The same document flags Brazil's affine row as degenerate (scalars up to 4.8) and optimistic. `incumbent()` takes the minimum over time slices even at the configured k, so the affine figure is still chosen on the test year. Being close to a fit known to be broken is not a headline. The mechanism contradicts the document too: section 4 refutes physiographic coverage as a predictor of which regions gain.

**Cheaper test.** No training is needed. Score both columns on identical rows from artefacts already on disk. The proposal scores affine on harness common rows and the model on its own rows, which is the same mismatch behind the CL correction notice of 2026-09-11. Then resample Brazil's 2024 units for the difference. The gap is 0.0008, about the size of the seed spread (0.0002 to 0.0011). If the interval spans zero, "within 1%" says nothing.

**Simpler explanation.** A degenerate affine fit, the row-set mismatch, or a single test year (2024) that happens to suit the model. Brazil's hub heights are all the 100 m default, so terrain inputs carry less there than the mechanism implies.

**Kill criterion.** As written, none: the gate is already known to pass. A real one would be: on identical rows, against a non-degenerate affine at the configured setting, drop the claim if the ratio exceeds 1.01 or the bootstrap interval is wider than ±1%.

**Opportunity cost.** The affine column, RF transfer, P2 and the fresh-region table are still not tied to a commit. The P1 margins for the US (0.0025) and UK (0.0027) have not been resampled. The #67 weighting preregistration is still parked.
