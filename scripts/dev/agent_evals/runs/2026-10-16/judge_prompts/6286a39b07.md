## The problem

The joint national offset fit minimises a squared capacity-factor error of
about 1e-4 with L-BFGS-B at ftol 1e-6. L-BFGS-B divides the change in the
objective by max(|f|, 1), so with f far below 1 the ftol acts as an absolute
threshold: a fit whose first step lowers the error by less than 1e-6 stops
there and reports success with the offsets still at or near their zero start.
Offsets near zero, and success=True, are then artefacts of the stopping rule,
not evidence that no offset is needed.

## The review

**Verdict: REVISE**

**Blockers**

1. **The tolerance change alters the method used for production fits.** The fit's options are hardcoded at `src/vwf/correction.py:326`, `options={"maxiter": 50, "ftol": 1e-6}`. Changing that line changes every country-level fit made through `src/vwf/harness/corrections.py:443`. That moves the realdata pins `fr_country_k10` and `es_country_k4` in `tests/test_pin_offset_fits.py:41-42`, along with every row in the country scorecard. Tighter tolerances with `maxiter` still at 50 also mean more "did not converge" refusals (`correction.py:331`). Fix: add `ftol`, `gtol` and `maxiter` as keyword arguments whose defaults are the current values (scipy's default `gtol`). Only the diagnostic passes the tighter values. Run `python scripts/dev/stamp.py realdata` and show that no pin moved.

2. **The gate cannot answer the claim.** One national observation leaves the N offsets under-determined by N-1 (`src/vwf/data.py:259-263`, `src/vwf/harness/corrections.py:523-528`). Each offset is wherever L-BFGS-B stops from zero, so the "every offset within 0.1 m/s" gate depends on k, not on physics. The mechanism is also misstated: the scalar is a ratio of observed to simulated capacity factor (`corrections.py:524-525`), not an estimate of wind-speed bias.

3. **"Could be dropped" is a predictive claim, and the proposal names no test year.** That breaks the rule in `AGENTS.md` that every result states its single test year. The project already has the control for this question: the registered `scalar-only` correction (`src/vwf/harness/corrections.py:520-581`, `tests/test_country_offset_controls.py`). Fix: score `affine-wind` against `scalar-only` through the harness on each country config's held-out year. If a training diagnostic is still wanted, gate on the gap the scalar alone leaves in capacity factor, `|sim(scalar, 0) - obs|`, which is identified.

4. **The synthetic check has no clean positive or negative.** A gap of -1e-3 starts at a squared error of exactly 1e-6, which sits on the acceptance threshold. Fix: use 3 or more clusters, and include gaps well above the threshold that must close, plus a zero gap whose offsets must stay at 0.

**Plan**
1. `src/vwf/correction.py`: add the keyword arguments. Add a fast test to `tests/test_country_offset_refusal.py` that monkeypatches `minimize` and checks the default options are passed unchanged. Run `mypy`, `lint-imports` and the realdata stamp.
2. Add the fast synthetic closure tests from blocker 4.
3. Put the driver in `scripts/studies/scorecard/`, modelled on `training_objective_check.py`. It parses with `make_parser`, uses public `vwf` names only, writes a manifest, runs through `scripts/dev/run_locked.py` and writes under `output/`. Record the tolerances in the manifest.
4. Pre-register the gate before the run.

**Risks**

- Refusals that cluster in hard periods would push the share up.
- With N-1 free directions, near-zero offsets can come from where the optimiser started rather than from the data.
